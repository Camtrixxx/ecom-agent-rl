# D2 预注册：新采的数据值不值得换基线

写在 2026-08-13 22:05，**SFT-v2 还没开始训**，任何 v2 的数字都不存在。
规则和门槛在这里定死，跑完照着念。**本文件此后不再改动**，结果写进
[roadmap.md](roadmap.md)。

## D2 是什么

把 D1 重采到的轨迹并进 SFT 训练集，重训 SFT，再从新的 SFT 起点重跑 GRPO。
数据侧不需要新代码：`build_sft_dataset.py --trajectories` 本来就接多份轨迹。

## 先算账（这些数在跑之前就已知，不是结果）

`select()` 是 `dedupe_by_task=True`，每个任务只收一条，所以「样本数」＝「有示范的任务数」。

| | 任务数 | 占 3000 池 |
|---|---|---|
| v1 已覆盖 | 1,781 | 59.4% |
| 新增 | **+371** | +12.4 个百分点 |
| v2 覆盖 | **2,152** | 71.7% |

**新增是 371 而不是 408。** 408 是只按 `reward_type` 数出来的（我在
`sft_train_retry.metadata.json` 里记的就是这个数）；构建器还要过 `max_rejections ≤ 3`、
`status == done`、`dropped_tool_calls`、`has_error`。有 37 条买对了但过程不干净。
以构建器的 2,152 为准——这正是「两处口径各算一份」会咬人的地方。

数据量 **+20.8%**（1,781 → 2,152）。

### 新数据不针对瓶颈，这是本次最重要的一条事前认识

按难度段看重采填补了各段多少缺口：

| 难度 | 池内 | v1 覆盖率 | 新增 | v2 覆盖率 | **新增填补该段缺口** |
|---|---|---|---|---|---|
| 1-2 | 530 | 60.8% | 62 | 72.5% | 29.8% |
| 3-4 | 1100 | 61.4% | 125 | 72.7% | 29.4% |
| 5-7 | 1078 | 57.4% | 144 | 70.8% | 31.4% |
| 8+ | 292 | 56.5% | 40 | 70.2% | 31.5% |

**四段的填补率几乎相同（29.8%–31.5%）。** 教师重采的成功率和约束数基本无关。所以 D2
是**均匀扩容**，不是针对性补数据。这一点事前并不明显——「能捞回来的都是简单题」和
「专补难题」两种猜测都被否掉了。

直接后果：roadmap 里那个未解决问题（**8+ 段错买率 0.100，GRPO 推不动**）**不会**被 D2
优先解决。8+ 覆盖率确实从 56.5% 涨到 70.2%，但和其他段涨得一样多。

### 预期效应 vs 噪声：这是本次实验最难的一点

+20.8% 数据 = **0.27 个倍增**。本项目**没有**测过数据量-成功率的斜率，所以只能用外部
先验：SFT 阶段每倍增数据换几个点，取 3–6 pp/倍增，则预期 **0.8–1.6 pp**。

而 R1 刚量出 run 间标准差 **s = 1.37 pp**。两个单 run 之差的 run 标准差是
1.37 × √2 = **1.94 pp**，95% 带宽 ±1.96 × 1.94 = **±3.8 pp**。

**预期效应（0.8–1.6 pp）远小于单 run 对比的噪声带（±3.8 pp）。** 所以：

> **一个 v2 run 的差值，无论正负、无论多大，都不足以单独支撑「新数据有用」或「没用」。**

这句话必须在跑之前写下来，否则跑完看到一个 +2.5 pp 会很难不把它当成结论。

## 判定规则

### 主判定：端到端（GRPO-v2 vs GRPO-v1 seed 42）

500 题 × k=4，按 task_id 配对。

- **|delta| ≤ 3.8 pp** → **无法与 run 运气区分**。不是「没有效应」，也不是「有效应」。
  报点估计和配对区间，明确写「单 run，不可归因于数据改动」。
- **|delta| > 3.8 pp** → 方向性发现。仍是单 run，**不足以据此换基线**，要补种子才能定。

阈值 3.8 pp 的来源是 R1 实测的 s = 1.37 pp。**注意这是借用**：s 量的是「固定 SFT 起点下
GRPO 的 run 间散布」，而 v2 换了 SFT 起点。借用的理由是没有更好的估计，代价是这个阈值
本身有不确定度。写在这里而不是事后解释。

### 次判定：SFT 侧（可解析的那一半）

SFT 只要 ~2 h，所以这一侧能真正做出区间来。跑 **3 对 3**：

- v1 侧：已发布的 `sft`（seed 42、6 卡）+ 新跑 seed 43、44
- v2 侧：`sft_v2` seed 42、43、44

统计量：两侧成功率均值之差，合并方差，t(df=4) = **2.78** 的双侧 95% 区间。

- **区间不跨 0** → 新数据在 SFT 侧有效，可以据此换基线。
- **区间跨 0** → 结论降级，**不补第 4 个种子**（同 R1 规则 2 的理由：不显著就加种子会把
  假阳性率从 5% 推到 20% 以上）。

**只有这一条能支撑「换不换基线」的决定。** 主判定的端到端数是给人看的，次判定才是有
分辨率的那个。

## 什么保持不变（否则测的不是数据）

- 训练配方与 v1 **逐字一致**：3 epoch、余弦退到 0、lr 1e-5、warmup 0.03、grad_accum 4、
  tokens_per_batch 32768、max_length 32768、weight_decay 0、max_grad_norm 1.0、sdpa
- **6 卡（GPU 2-7）**。`train_sft.sh` 默认是 7 卡（1-7），必须显式改成 6 卡：
  global batch = grad_accum × 卡数，7 卡是 28、6 卡是 24。卡数一错，数据量就和卡数
  混在一起，而那是这个实验唯一要量的东西。本轮反复踩过这个坑。
- held-out 池不变（`data/task_pools/sft_val.jsonl`，500 题），评测池不变
  （`evaluation.jsonl`，500 题 × k=4 × temperature 0.7）
- GRPO-v2 超参与 seed 42 **逐项一致**，只改 `init_model` 指向 `sft_v2`
- 环境代码内容锚必须匹配 `734d7100…bae613`（46 文件）；不匹配就中止，不是警告

**会变的一项，记在这里**：样本多了 20.8%，optimizer step 从 81 涨到约 98。这是「更多
数据」的一部分，不是混淆项——但它意味着 v2 的总 LR 积分比 v1 大，而 E2 刚证明总 LR
积分本身能值 6.71 pp。**这是本次实验一个无法消除的混淆**：在固定 epoch 数的配方下，
加数据必然加 step。要拆开它需要第三个 arm（v2 数据、step 数对齐到 81），本轮不做，
但结论里必须写明这一点，不能把「加数据」和「加 step」当成同一件事的两种说法。

## 次要预测（写在看到任何数字之前）

1. SFT-v2 − SFT-v1（3 对 3 均值差）落在 **0 到 +3 pp**，最可能 +1 到 +2 pp。
2. **8+ 段错买率不改善**（v1 是 0.100）。这是从「新数据不针对瓶颈」直接推出来的，
   是本次最有判别力的一条——如果 8+ 段明显改善了，说明我对这批数据的理解是错的。
3. GRPO 在 v2 起点上的增益仍在 **+5 到 +11 pp**（R1 的区间），即 GRPO 的贡献不太依赖
   SFT 数据量。若它显著缩小，说明 SFT 和 GRPO 在抢同一批可学的东西。
4. `early_abstain` 在所有 v2 产物里保持 **0**。
5. SFT-v2 的 val loss 会比 v1 的 0.39249 **高**（val 集不变，训练集变难：新增的 371 条
   全部来自教师首采失败的任务）。**val loss 变高不等于模型变差**——这条写在这里，是为
   了防止半夜看到 val loss 涨了就以为跑坏了。
