# #29 · 三份 GRPO 快照同窗口重评的判读规则

**写于 2026-08-16 06:50，四条腿一条都没起，一个新数都没有。** 已见的只有**已发布的**三个
配对 delta（+7.41 / +9.75 / +7.36 pp，s = 1.37 pp）——那是本臂的比较对象，不可能不看。

---

## 要拆的东西

R1（roadmap「+7.41 pp 在 run 间稳不稳」一节）用三个 seed 量出 **s = 1.37 pp**，并由它推出
一句被 roadmap 到处引用的实用判据：

> **单个 run 上小于约 1.4 pp 的差值，和「seed 运气」分不开。**

#28 发现这把尺子可能偏粗。三个 GRPO seed 共用同一份 SFT 底座（`train_grpo.py:82` 的默认
`outputs/models/sft`），三份权重却评于**三个不同时刻**（08-12 12:39 / 08-13 20:57 /
08-13 21:35）。所以

    1.37 pp 的散布 = 三次 GRPO 训练的水平散布 ⊕ 三次评测各自的漂移

和 #28 里已发布组内 s（1.20 / 1.12 pp）→ 同窗口 s（0.46 / 0.59 pp）那一次收缩是同一个结构。
**把三份快照放进一个窗口重评，漂移项被压到窗口内水平，剩下的才是纯训练方差。**

## 方向上先说清楚：这条臂翻不掉任何已发布的「不跨 0」

尺子变细只会让"分不开"这句话说得**更晚**（判据更宽松），不会让任何已发布的正结论翻掉——
R1 的 +8.17 pp 是 6 个 s，s 缩小只会让它更稳。**唯一有风险的是那句偏保守的 1.4 pp 经验判据。**
先写在这里，是为了防止我看到一个漂亮的小 s 就把它读成比它实际更大的胜利。

## 主判定：同窗口的三个 delta 有多散

对每个 seed，拿新轨迹对**同一份、未重采的** `outputs/rollouts/sft.jsonl` 按 task_id 配对
（`report_metrics.py`，和 R1 逐字同一口径），得 d′ᵢ；

    s′ = stdev(d′₄₂, d′₄₃, d′₄₄)      ← 主统计量，和已发布的 1.37 pp 比

**为什么仍配旧基线而不是新跑的 `gv_sft`：** 要和 1.37 pp 比，就必须用产生 1.37 pp 的那个口径。
换成新基线会同时改掉减数和口径，比出来的差没法归因。而且减数是常数、在 s′ 里约掉，
所以"旧基线已经漂移了"这件事**不影响主判定**——它只平移三个 delta，不改它们的散布。

**闸门**：`sft.jsonl` 必须还是 R1 用的那一份。跑前记下指纹，脚本启动时复核：

    sha256  57a85d0d75bb6bc6ca2145b2c766ccb758f2e60c8749d5b8be735d3a5e766da7
    行数    2000        mtime 2026-08-11 18:12        单侧成功率 0.6061

对不上就拒跑——那意味着有人重跑覆盖了它，而 R1 的 1.37 pp 是在旧文件上算的，两边不可比。

**自检**：脚本启动时先用**已发布的**三份报告复算 d̄ 与 s，必须复现 +8.17 pp / 1.37 pp
（容差 0.02 pp）。复现不了说明本脚本的统计口径和 R1 不一致，判定不可信，直接退出。

### 先承认这条臂几乎没有检验力

n=3 估标准差，df=2。方差比 F = 1.37² / s′² 的单侧 0.05 临界值是 **F₀.₉₅(2,2) = 19.0**，
即要宣称"显著变小"需要 **s′ < 1.37/√19 = 0.31 pp**——比窗口内重评噪声底（0.39 pp）还小，
实际上不可能达到。σ 的 χ² 区间在 df=2 下是 [0.52 s′, 6.29 s′]，宽到没有约束力。

**所以下面的分支全是点估计分支，是方向性的，不是显著性检验。** F 值照算照登，预期不显著；
**任何写进 roadmap 的措辞都必须带"n=3、方向性、不显著"这三个字眼。** 这条现在写死，
免得出了个 0.5 pp 就把它说成"证明了"。

### 分支（阈值现在定死，依据见括号）

阈值取自 #28 实测的收缩倍率：已发布组内 s 1.20 / 1.12 pp → 同窗口 0.46 / 0.59 pp，
即 0.38× / 0.53×。若 GRPO 侧收缩倍率相同，s′ 应落在 0.52–0.73 pp。

- **s′ ≤ 0.70 pp** → 与 #28 的收缩倍率一致。判读：**σ = 1.37 pp 确实高估了纯训练方差**，
  roadmap 那句悬着的猜测改成"已检验，方向性成立"。实用判据从"约 1.4 pp"改成
  "约 s′ pp"，**并注明 n=3、不显著**。所有引用 1.4 pp 那把尺子的地方要标注新值。
- **0.70 pp < s′ < 1.10 pp** → **不定**。两把尺子并列照登，roadmap 措辞一个字不改，
  只补一行"同窗口重评得 s′ = X pp，n=3，分不出"。
- **s′ ≥ 1.10 pp**（≥ 1.37 的 80%）→ 收缩没有发生。判读：**"σ 多半高估纯训练方差"那句
  不成立**，在 roadmap 里标成**已检验、不成立**，1.37 pp 基本就是训练方差，1.4 pp 的
  判据原样保留。

三个分支覆盖全实轴，没有留缝。

## 附带产出（不作判定，但必须记）

**1 · 纯训练标准差的点估计。** 窗口内同权重重评的噪声底是 **0.39 pp**（#14 的锚，同一份权重
重评三次）。于是

    σ_train ≈ sqrt(s′² − 0.39²)

若根号内为负，报"**低于噪声底，测不出**"，**不报 0**——那是"这把尺子分不开"，不是
"训练方差是零"。两者在后续引用里会被读成完全不同的话。

> **08-16 07:55 事后追加（原文一个字没改，规则也不改）：这里引的 0.39 pp 已停用。**
> #29 由四条腿的 bootstrap 配对半宽（1.99/1.93/1.95/1.83 pp）反解出单次评测噪声
> **σ_m ≈ 0.70 pp**，是它的 1.8 倍——#14 那个锚是 n=3、df=2 的标准差，抽小了。
> 见 `docs/roadmap.md`「尺子变细之后」一节。
>
> 用 σ_m = 0.70 pp 重算：s′ = 0.63 pp ≤ σ_m，**纯训练方差测不出**——正好落进
> 上面预先写好的"不报 0"那一支。所以**这一项的结论按上面的规则走，
> 但印出来的 0.49 pp 是假数，不要引用。**

**2 · 第一次完全同窗口的 GRPO 增益。** 已发布的 +7.41 / +9.75 / +7.36 pp 都是"新 GRPO 对
08-11 的 SFT"，跨 1–3 天。本臂的 `gv_sft` 把减数也拉进同一个窗口：

    同窗口增益 = mean(三条 GRPO 新腿) − gv_sft

限定必须跟着一起引用：SFT 侧只有 **n=1**，所以这个数**不含 SFT 侧的训练 run 方差**
（和 R1 一样，R1 的基线也是单份未重采）。它回答的是"同窗口下增益还有多大"，
不是"增益的总不确定度"。逐 seed 的配对 bootstrap 区间也一并出。

**3 · 三个 δᵢ = 新值 − 已发布值，间隔 3–4 天。** 给漂移数据集再添三个点。而且三条腿同窗口，
所以 stdev(δᵢ) 是**权重相关漂移分量**的又一次估计，可以和 #28 的 s = 0.62 pp 比。
注意这三份权重的间隔（08-12/08-13 → 08-16）落在"≥ 40 h"那一档，按 roadmap 阶段 C 的
经验规律预期 1.6–2.3 pp 且**符号随机**——所以 δ 本身的大小说明不了什么，看的是它们的散布。
