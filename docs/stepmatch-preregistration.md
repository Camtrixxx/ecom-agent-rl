# #14 步数对照臂的判读规则

**写于 2026-08-15 23:58，s43 的评测在 108/2000 行、s44 还没开始训。**

## 这条臂要拆的东西

D2 的 SFT 侧配对差 +5.42 pp（`sft_v2` vs `sft`）里混着两个东西：

1. **数据效应**——v2 的教师轨迹本身更好；
2. **LR 积分效应**——v2 数据多，同样 3 个 epoch 下步数从 81 涨到 102，多走了 21 步。

> **08-16 04:40 更正数字（不是改判读规则）**：这里原先写"从 76 涨到 102、多走 26 步"。
> 76 是我凭印象写的，没查。从 train log 数出来的真实步数是 `sft` = **81**、`sft_v2` = 102、
> `sft_stepmatch_*` = 102，和 roadmap 那张权威表一致。所以增量是 **81 → 102 = +21 步
> （+25.9%）**，不是 +26 步。判读规则、阈值、结论一个字没动——改的只是"多走了多少步"这个
> 被减数，而它是整条臂归因时读者会直接引用的数。

`scripts/run_d2_stepmatch.sh` 用 **v1 数据训到 102 步**，把第 2 项对齐。于是

    stepmatch（v1 数据，102 步）  vs  sft_v2（v2 数据，102 步）  =  纯数据效应

## 披露：这不是盲的

s42 的两个数我**已经看过**：`sft_stepmatch_s42` = 0.6507，`sft_v2` = 0.6626，配对 −1.33 pp。
s43 在跑、s44 没开始，这两个是盲的。所以下面的规则对 2/3 的数据是预注册的，对 s42 不是。
写下来就是为了不让"看完三个数再挑口径"这件事发生。

## 主判定用哪个基线：**同窗口锚**，不是 08-14 那组

08-15 晚上量到跨 session 漂移约 2 pp 且符号随机（见 optimization-log 08-15 21:35）。这条臂
受害尤其重，因为**两组的评测日期是整组错开的**：

| 组 | 成员评测时刻 |
|---|---|
| stepmatch | s42 08-15 20:37 / s43 08-15 23:47 / s44 约 08-16 02:00（跨午夜三个窗口） |
| sft_v2（已发布） | s42 08-14 03:58 / s43 08-14 16:19 / s44 08-14 18:38（同一天） |

整组错开意味着漂移不是噪声而是**偏置**：它整体加在差值上，多少个 seed 都平均不掉。
s42 已经把这件事演示了一遍：

| 基线 | stepmatch_s42 − 基线 |
|---|---|
| `sft_v2`（08-14 03:58，已发布） | **−1.19 pp** |
| `sft_v2_resample`（08-15 21:34，与 s42 评测同窗口重叠） | **+1.06 pp** |

**符号翻了。** 和 D2 主判定换基线时 +0.51 → −1.60 pp 是同一个病。

所以主判定定为：**每个 stepmatch seed 配一份在它自己评测窗口内重评的 `sft_v2`**，
差值逐窗口算，再对三个窗口做 n=3 的 t 检验。三份锚：

| 窗口 | stepmatch | sft_v2 锚 | 状态 |
|---|---|---|---|
| 08-15 20:40 | s42 | `sft_v2_resample` | 已有 |
| 08-15 23:50 | s43 | `sft_v2_resample2` | 在跑 |
| 08-16 02:00 | s44 | `sft_v2_resample3` | **待起，见下** |

注意锚是**同一份权重**重评三次，不是三个 seed——v2 侧的训练 run 方差因此**没有**进这个
区间。这是刻意的：这条臂问的是"v1 数据 vs v2 数据"，v2 侧的 seed 方差已经在 3 对 3 那里
单独量过（s = 1.12 pp）。真要都要，得 3 seed × 3 窗口 = 9 次评测，不值。
**引用时必须带这句限定**，否则会把这个区间当成含双侧训练方差的。

次判定（naive）：stepmatch 三条 vs 已发布的 `sft_v2/_s43/_s44` 三条。**这个数会照登，但
不作主判定**，理由就是上面那张整组错开的表。两个判定不一致时以同窗口锚为准，并把不一致
本身当成漂移量级的又一次测量记下来。

## 判读分支（三个 seed 齐了之后执行，不再改）

设 d = mean(stepmatch) − mean(sft_v2 锚)，n=3，t₂,₀.₉₇₅ = 4.30。

- **d 的区间跨 0** → 结论：**在匹配步数之后，v2 数据没有可测的额外收益**。那么 D2 SFT 侧
  的 +5.42 pp 主要是 LR 积分（多走 21 步），而不是教师数据质量。这会直接改 roadmap 里
  "重采教师数据有效"的措辞——有效的可能是"多训 21 步"，而那个便宜得多。
- **d 显著为负（stepmatch 低于 sft_v2）** → v2 数据确有额外收益，+5.42 pp 里数据占 |d|、
  LR 积分占余下。按 |d| 的大小决定要不要继续投数据。
- **d 显著为正（stepmatch 反而高）** → v1 数据在 102 步下更好，v2 数据的收益全部来自步数
  且带负号。这个方向如果出现，**先怀疑漂移没被锚干净**，去看三个窗口的锚值离散度：若锚
  自己的 s 就有 1 pp 量级，说明同窗口也压不住漂移，那这条臂在现有评测精度下**做不出结论**，
  该记成"测不动"而不是硬报一个数。

**08-14 的预注册期望是 +4.4 pp（即 stepmatch 应显著低于 sft_v2）。** s42 单点是 −1.33 pp，
方向对但量级差 3 倍多。若三个 seed 齐了仍在 ±1.5 pp 内，那条 +4.4 pp 的期望就是被证伪的，
要在 roadmap 里明写证伪，不是"未达预期"。

## 一个已知的不对称，认了但要记

stepmatch 三条分三个窗口评、跨午夜；`sft_v2` 那三条在同一天评。同窗口锚修的是**组间**偏置，
修不了 stepmatch **组内**三个窗口各自的漂移——那部分会进 stepmatch 组的 s，把区间撑宽。
方向是保守的（更难显著），所以不额外补救。若最后 stepmatch 组的 s 明显大于 3 对 3 实测的
1.2 pp，那个超出量就是窗口漂移的估计值，顺手记下来。
