# GRPO 评测预注册

**写于开跑之前**，2026-08-12。目的只有一个：把判定规则钉在看到数字之前。

「不显著就加采样，直到显著为止」是一个会把假阳性率从 5% 抬到 20%+ 的做法，而它在
过程里看起来完全合理。唯一的防线是提前写下升级条件，并且**无论结果如何都按它执行**。

## 为什么需要这份文件（分辨率的实测）

拿 SFT 自己的 2,000 条按 `attempt % 2` 切成两半做配对比较——**真实差值为 0**，
量出来的区间就是这套流程的噪声下限：

```
495 题配对，差值 −0.0040 [−0.0323, +0.0253]     # k=2
```

按题内成功率方差 E[p(1−p)] = 0.0837、n = 490 外推
（半宽 = 1.96 × sqrt(2·E[p(1−p)]/k/n)，并按上面实测的 1.13× 修正）：

| k | 半宽（真差值 = 0） | 每模型回合数 |
|---|---|---|
| 1 | ±4.1 pp | 500 |
| 2 | ±2.9 pp（实测） | 1,000 |
| 4 | ±2.0 pp | 2,000 |
| 8 | ±1.5 pp | 4,000 |
| 16 | ±1.0 pp | 8,000 |

参考实现的 GRPO 增益是 **+1.5 pp**——落在 k=4 的噪声里，量不出来。本项目训练期
`gold_purchase` 从 56.2% 涨到 71.6%（温度 1.0，非评测口径），若能迁移一部分到留出集
则远大于 k=4 的分辨率。所以先跑 k=4 是合理的赌注，但赌输了要按规则加钱，不是改规则。

## 口径（与 baseline / SFT 逐字一致）

| 项 | 值 | 来源 |
|---|---|---|
| 任务池 | `data/task_pools/evaluation.jsonl`，500 题 | 与 baseline/SFT 同池 |
| 池子污染 | `eval ∩ sft_train = 0`，`eval ∩ grpo_train = 0` | 已核 |
| k | 4（每题 4 次采样） | 同 baseline/SFT |
| temperature / top_p / max_tokens | 0.7 / 0.95 / 1024 | `run_rollout.py` 默认值 |
| top_k / repetition_penalty | 20 / 1.05 | 四个模型的 `generation_config.json` 逐字节一致 |
| max_model_len / 压缩窗口 | 24576 | `serve_model.sh` 默认 |
| max_steps | 35 | 默认 |
| concurrency | 16 | 同 SFT 评测 |

**GRPO 训练时用 temperature 1.0，评测必须用 0.7**——评测比的是同一条件下的策略质量，
不是各自最优采样温度下的质量。

## 主假设与判定规则

**主指标**：`report_metrics.py` 的配对 bootstrap 差值——按 `task_id` 先取题内平均，
再对题做 bootstrap，95% 区间。配对消掉题目难度方差。

**主比较**：GRPO policy（`iter039`）vs SFT。

判定：

1. **区间不跨 0** → 结论成立，按符号报「GRPO 提升/降低了 N 个点」，**停在 k=4**。
2. **区间跨 0** → 触发升级：SFT 与 GRPO 双双补采到 **k=16**（各再补 6,000 条），
   以 k=16 的区间为最终结论。**k=4 的结果同时报出**，不挑好看的那个。

升级只做一次，k=16 之后无论结果如何都收工。若 k=16 仍跨 0，结论就是
「在 ±1.0 pp 的分辨率下测不出 GRPO 与 SFT 的差异」——这是一个有信息量的结论，不是失败。

**次要比较**：GRPO vs baseline。差值量级在 +50 pp 以上，k=4 绰绰有余，不参与升级判定。

## 预注册的次要预测

这几条是在看到数字之前写下的，用来区分「解释」和「事后编故事」：

1. **增益必须落在「条件买对率」上。** SFT 的走到终局率已经 0.9950（天花板），
   乘性分解里格式那一项没有空间了。若 `decompose_success.py` 报出 GRPO 的增益主要
   来自格式项，说明分解逻辑或数据有问题，不是模型学到了什么。
2. **错买率应当下降，且高难度桶降得更多。** SFT 的错买率随 `attributes` 数单调上升
   （0.0275 → 0.0533 → 0.0576 → 0.0996），roadmap 判定瓶颈是约束核验，GRPO 的
   −0.85 惩罚正是冲它去的。**这是本次评测最硬的一条预测**：它有方向、有分层形状，
   猜中的先验概率低。
3. **`repeat_loop` 占比应当下降。** 训练期每 192 条从 32 降到 8。若留出集上不降，
   说明降的是训练集上的过拟合。
4. **`early_abstain` 应当保持 0。** SFT 已经从 11.25% 压到 0，GRPO 不该把它推回来
   （−0.35 比 −0.85 轻，一个学会「不确定就别买」的策略会回到弃买）。**若它回升，
   即使成功率上去了也要单独报**——那是在用弃买换错买率，不是能力提升。

## 探索性（不参与主结论）

`iter019` vs `iter039`，k=4。用来回答「后半程 20 轮有没有白跑」：训练期无方差而被
丢弃的组从 4.6/24 涨到 10.2/24，进梯度的轨迹从 163 掉到 96，后半程每轮实际学习量
只有前期六成。

这一项**没有预设阈值也不做显著性声明**。k=4 的 ±2.0 pp 分辨率下，两个相邻检查点
大概率测不出差异；「测不出」在这里本身就是有用的信息（说明该早停）。它只影响下一轮
实验怎么配，不影响本轮结论。
